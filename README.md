# AI팀 휴가 캘린더

달력에서 그날 누가 휴가인지만 본다. 사이트에서 바로 등록하면 그 사이트를 보는 사람 전원에게 반영된다.
구글 시트나 외부 서비스 없이 **사이트 자체가 저장소**다.

| 파일 | 용도 |
|---|---|
| `public/index.html` | 화면 (마크업 + 스타일) |
| `public/app.js` | 동작 전체. 인라인 스크립트를 쓰지 않는 이유는 아래 **보안** 참고 |
| `public/data.js` | 2026 공휴일 표 + 로컬에서만 쓰는 예시 목록 |
| `public/fonts/` | 나눔스퀘어라운드 400·700·800 (self-host) |
| `netlify/functions/leaves.mjs` | 일정 API (Netlify Blobs 에 저장) |
| `netlify.toml`, `package.json` | 배포 설정 · 보안 헤더 |
| `test_leaves.mjs` | 서버 입력 검사 테스트 |
| `시안_8종.html` | 디자인 시안 비교용. 확정됐으면 지워도 된다 |

**`public/` 만 배포된다.** 예전엔 `publish = "."` 이라 함수 소스·`package.json`·테스트까지
정적으로 그대로 서빙됐다(레포를 비공개로 돌려도 소스만 공개로 남는 상태였다).

주말·공휴일은 전원 휴무이므로 그 칸에는 휴가자를 표시하지 않는다.

---

## 배포

```bash
npm install
npx netlify deploy --prod
```

처음이면 `npx netlify login` → `npx netlify init` 로 사이트를 만든 뒤 위 명령을 실행한다.
Netlify Blobs 는 사이트에 기본 포함이라 따로 만들 것이 없다.

배포되면 팀즈 채널 → `+` → **웹사이트** 탭 → 배포된 주소.
`netlify.toml` 의 CSP `frame-ancestors` 가 팀즈에서만 임베드를 허용한다.
다른 곳에 붙이려면 그 도메인을 `frame-ancestors` 에 추가해야 한다.

---

## 쓰기 권한 (읽고 넘어갈 것)

배포된 주소에는 로그인이 없다. 즉 **주소를 아는 사람은 보는 것도, 등록·삭제도 된다.**
사내에서만 도는 주소라면 그대로 써도 되고, 잠그려면 환경변수 하나만 넣는다.

Netlify 사이트 설정 → Environment variables →

```
TEAM_PASSCODE = 팀에 공유할 암호
```

넣으면 등록·삭제할 때 암호를 한 번 묻고, 그 탭에서는 기억한다(보기는 암호 없이 된다).
안 넣으면 암호 없이 누구나 쓸 수 있다.

---

## 쓰는 방법

- **등록** — 상단 `일정 등록` 버튼, 또는 달력에서 **빈 날짜 칸을 클릭**하면 그 날짜로 폼이 열린다.
  이름·시작·종료(생략하면 하루)·메모·색을 넣고 등록. 등록한 달로 화면이 넘어가고 칩이 튕겨 들어온다.
- **수정** — 달력의 **이름 칩을 클릭**하면 그 내용이 폼에 채워진 채 수정 모드로 열린다.
  고쳐서 `수정`, 없앨 거면 그 안의 `삭제`. 키보드로도 된다(칸·칩에 Tab 이동 후 Enter).
- **색** — 고르지 않으면 이름별로 자동 배정된다. 한 번 고른 사람의 이름을 다시 입력하면
  그 색이 자동으로 선택되므로 같은 사람이 여러 색이 되지 않는다.
- **삭제 되돌리기** — 삭제 후 메시지에 `되돌리기` 버튼이 뜬다. 놓쳐도 `?trash=1` 로 되찾을 수 있다.
- 다른 사람이 올린 건 **1분마다** 자동으로 반영된다(탭이 보일 때만).

## 검증

```bash
node test_leaves.mjs
```

서버 입력 검사(없는 날짜, 종료일 역전, 이름·메모 길이, 1년 초과, 연도 상하한,
제어문자·제로폭 제거)를 확인한다.

화면 쪽은 브라우저 콘솔에서 `selftest()` — 격자 배치·월 경계·휴무일 처리,
**저장 XSS 페이로드가 실행되지 않는지**, 색 대비 값, 키보드 도달 가능성,
칩 줄바꿈, 배경 반응까지 한 번에 본다. 로직을 고쳤으면 둘 다 돌린다.

## 보안

무인증 공개 엔드포인트라는 전제로 막아 둔 것들.

| 항목 | 조치 |
|---|---|
| 저장 XSS | 이름·메모를 출력할 때 이스케이프(`esc()`). 실제로 실행됐던 취약점이다 — 메모 40자 안에 `<img src=x onerror=…>` 가 들어간다 |
| XSS 2차 방어 | CSP `script-src 'self'` — 그래서 스크립트를 `app.js` 로 뺐다. 이스케이프가 뚫려도 인라인 핸들러가 실행되지 않는다 |
| 전체 삭제 | 삭제는 지우지 않고 `trash/` 로 옮긴다. `GET /api/leaves?trash=1` 로 되찾을 수 있고, 화면에도 되돌리기 버튼이 뜬다 |
| 자동 스팸·대량 삭제 | 같은 IP 분당 쓰기 20회 제한, 목록 상한 500건 |
| 다른 사이트에서 몰래 쓰기 | POST 에 `content-type: application/json` 강제 (단순 요청으로 우회 못 함) |
| 소스 노출 | `public/` 만 배포 |
| 임베드 | CSP `frame-ancestors` 로 팀즈에서만 |
| 값 깨짐 | 제어문자·제로폭·양방향 제어문자 제거, 날짜는 2020~2100 만 |
| 색 | hex 대신 팔레트 인덱스(`ci`, 0~11)만 받는다 — 검증이 단순해지고 출력에 색 문자열이 새지 않는다 |

되돌릴 수 없는 것을 남기지 않는다는 원칙이라, **삭제는 영구 삭제가 아니다.**
`trash/` 는 자동으로 비워지지 않는다.

## 저장 방식 (기록이 날아가지 않는 이유)

레코드마다 blob 을 하나씩 쓴다(`leave/<id>`). 목록 전체를 한 blob 에 담아
읽기-수정-쓰기 하던 초기 방식은 **실제로 기록을 날렸다** — Netlify Blobs 기본값이
최종적 일관성이라 방금 쓴 값이 몇 초간 안 읽히고, 그 사이 다른 사람이 등록하면
예전 목록을 읽어 덮어썼다. `@netlify/blobs` 8.2 에는 조건부 쓰기가 없어 그 방식은
안전하게 만들 수 없다.

지금은 쓰기끼리 키가 겹치지 않으므로 덮어쓰기가 구조적으로 불가능하고,
`consistency:"strong"` 이라 등록·삭제가 즉시 조회된다.

`backups/` 는 실제 이름이 들어가므로 gitignore 돼 있다. 필요하면
`curl -s <사이트주소>/api/leaves > backups/$(date +%Y%m%d_%H%M).json` 로 받아둔다.

## 레이아웃

헤더는 `grid-template-columns: auto minmax(0,1fr) auto` 로 슬롯을 못 박았다.
예전에는 `flex` + `wrap` + `space-between` 이라 폭에 따라 내비가 아래 줄로 넘어가고
요약 위치가 매번 달라졌다(모니터마다 들쑥날쑥). 월 표시도 `7.6vw` 로 이어 붙여 크기가
계속 변했다 — 지금은 84 / 68 / 56px 세 단계뿐이다.

`.wrap` 이 1300px 에서 멈추므로 **1348px 이상 모니터에서는 내부 배치가 픽셀 단위로 동일**하다
(1920 과 1366 실측 결과 h1·요약·내비·칸폭이 전부 같았다).

격자는 `repeat(7, minmax(0,1fr))` 이어야 한다. `1fr` 은 min-content 를 존중해서
`nowrap` 칩이 든 칸만 넓어지고, 좁은 화면에서 격자가 화면을 넘어 가로 스크롤이 생겼다.

## 알려진 한계

- 목록을 읽을 때 레코드 수만큼 병렬 get 을 던진다. 상한 500건까지는 문제없고,
  그보다 커지면 키에 연도를 넣어 보고 있는 연도만 읽는 쪽으로 바꾼다 — `leaves.mjs` 주석 참고.
- 레이트 리밋 카운터는 읽기-수정-쓰기라 경쟁이 있다. 정확한 계량이 아니라 근사치로,
  자동 스팸을 늦추는 것이 목적이다.
- 배경과 폴링 모두 탭이 안 보이면 멈춘다(배경은 8초 무입력에도 멈춤). 다시 보면 즉시 최신화한다.
- 버튼은 `일정 등록` 이지만 주말·공휴일 칸에는 등록분을 표시하지 않는다(전원 휴무일 전제).
  주말 일정도 보여야 하면 `public/app.js` 의 `onLeave()` 에서 `isOff` 분기를 빼면 된다.
- `trash/` 는 자동 정리가 없어 계속 쌓인다. 목록 조회 성능에는 영향 없다(별도 prefix).
